  <action>
    Root cause (per UAT gap 2): SQLite `INSERT OR REPLACE` on a parent row with matching primary key performs DELETE-then-INSERT. Because CategoryEntity, BadgeEntity, and RequirementEntity declare `onDelete = ForeignKey.CASCADE`, any `upsertCatalog` / `upsertCategory` / `upsertBadge` call that REPLACE-conflicts on `id` silently deletes the entire child hierarchy and re-inserts rows with new auto-generated IDs. `CatalogSeedMergeTest` captures `baddarenGron.id` before `catalogDao.upsertCatalog(simidrott.copy(catalogVersion = "2020.01.01"))` (line 66–68); that version-downgrade upsert CASCADE-wipes badges/requirements, so post-merge `findRequirementByBadgeAndCode(badgeId = baddarenGron.id, code = "baddaren-gron-01")` returns null → NPE at line 100.

    Fix per D-13/D-15: In `CatalogDao`, replace all four `@Insert(onConflict = OnConflictStrategy.REPLACE)` upsert methods (`upsertCatalog`, `upsertCategory`, `upsertBadge`, `upsertRequirement`) with `@Upsert` (Room 2.8.4 already on classpath via libs.versions.toml). Add `import androidx.room.Upsert`. Keep `suspend fun` signatures and `Long` return types unchanged so `CatalogSeedLoader` call sites need no API changes.

    Do NOT change merge lookup logic in `CatalogSeedLoader` — the find-by-code → `toEntity(existingId)` pattern is correct once upserts update rows in place via `ON CONFLICT DO UPDATE` instead of delete-and-reinsert.

    Do NOT touch deferred UAT gap 1 (badge image artwork).
  </action>
